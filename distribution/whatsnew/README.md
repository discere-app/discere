# Play Store release notes

One plain-text file per locale, read by `r0adkll/upload-google-play` (see
`.github/workflows/release.yml`, `whatsNewDirectory` input) and pushed as the
"what's new" text for the Google Play release.

```
distribution/whatsnew/
  en-US/whatsnew
  de-DE/whatsnew
```

Rules, enforced by the "Validate what's new notes" step in `release.yml`:

- Plain text only — no markdown, Play doesn't render it.
- Max 500 characters per file (Play Store's hard limit).
- Must not be empty.

This is separate from `CHANGELOG.md` / the GitHub release notes generated by
`scripts/release/generate_changelog.sh`, which are grouped by commit type and
include internal changes (`refactor`, `chore`, `ci`) that aren't meaningful to
end users. These files should instead say what actually changed for someone
using the app, e.g.:

```
New: filter search results by habitat.
Fix: crash when switching decks mid-review.
```

## Workflow

Before tagging a release, edit both files to describe what's actually user-
facing in that release, and commit them alongside the version bump PR
(`scripts/release/bump_version.sh`). If you forget, the release still goes
out — Play just shows the notes from whatever was last committed here — but
the validation step fails the build if a file is empty or over the limit.
